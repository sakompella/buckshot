# Buckshot

Research on Buckshot Roulette: a multiplayer rules library in Bend, agent tools, and an arena where models play each other, with a site that shows its results.

- **Local notes:** `_work/AGENTS.local.md` (local, gitignored) holds setup-specific notes. Read it first when it exists.
- **Bend is the source of truth for the rules** (`sim/bend-mp/`). TypeScript may call Bend exports but never re-implements rules. Rules outside Bend (the Rust evaluator in `sim/rust/`) must be verified against Bend, and Bend wins any disagreement (ADR-0052).
- **Never commit** decompiled game code, original game assets or text, raw tournament data, anything under the gitignored `_work/`, or in-progress trackers (status notes, progress logs, handoffs, plans). Trackers go in `_work/` or `_*.md`. If one gets committed on a branch, purge it from the branch's history before the merge. Account ids and emails stay out of committed files.
- **Toolchain:** `nix develop` gives the pinned Bend 2.0.40, bun, Python and stable Rust. The Rust version lives only in `sim/rust/rust-toolchain.toml`: rustup reads it outside Nix, and the flake builds the same toolchain from it (rust-overlay).
- **`dev` commands:** the `buckshot-dev` package in `dev/` (uv project) provides the `dev` CLI — `dev heavy -- <cmd...>` runs a command niced holding one of two machine-wide heavy slots. Run it three ways: `uv run --project dev dev ...` (no Nix), `nix run .#dev -- ...` (Nix), or `dev ...` on PATH inside `nix develop`. Tool overrides for `dev`: `BEND`, `BENDTT`, `CARGO`, `BUN`. The shell scripts under `sim/` use `cargo` and `bun` from `PATH`.
- **Before committing:**
  - Bend changes: `bash sim/bend-mp/check.sh`.
  - `sim/rust/` changes: the pre-commit hooks run `cargo fmt --check`, `cargo clippy` with `-D warnings` on every feature set, `cargo check` and `cargo branch-map check` when `sim/rust/` files are staged (`sim/rust/hooks.sh`, listed in `sim/rust/pre-commit-config.json`). Install them once per clone with `bash sim/rust/install-hooks.sh`: it writes one hook file in the shared hooks directory (all worktrees use it, and it skips a checkout without `sim/rust/pre-commit-config.json`) and changes no git config; `nix develop` installs nothing. The hook runs `pre-commit` or `prek` from `PATH`: `nix develop` provides pre-commit, and without Nix install either one and rustup (it reads `sim/rust/rust-toolchain.toml`). `nix flake check` runs the same hooks on the whole tree. `check.sh` then also needs node, bun and Bend 2.0.40 on `PATH` or in `$BEND`. Also run `cargo test` and `cargo test --no-default-features --features f32,seats-2-4` from `sim/rust/` (`sim/rust/features.sh` lists the eight feature sets: `check.sh` runs clippy on all of them, and the tests for `f64` and `f32` on `seats-2-4` and `seats-2`, the `f32` ones for the search crate only). The search crate's `f64` (default) and `f32` features exclude each other, so never pass `--all-features`; `f32` is the Bend-exact build and the only one with the compat evaluator. To compare with Bend, run `bash sim/rust/check.sh`: it plays seeded Bend tapes and Bend player analyses (`sim/rust/search-oracle.sh`) and runs the tape replay and the search oracle with them, with no private data. Replaying recorded arena matches is a separate check: `bash sim/rust/check-arena.sh --db PATH` (or `BUCKSHOT_ARENA_DB`), which fails unless every requested match replays. Mutation testing is `bash sim/rust/mutants.sh` with cargo-mutants arguments (settings in `sim/rust/.cargo/mutants.toml`); not in the hook or `check.sh`. Run it in chunks of about 15 minutes through `dev heavy --`: `--package buckshot-rules --file rules/src/<file>.rs`, then `--package buckshot-search --no-default-features --features f32,seats-2-4 --shard k/4`. A surviving mutant fails it: add a test, or list the mutant in `exclude_re` with the reason it is equivalent or unreachable.
  - `web/` changes: from `web/`, run `bun run lint` (0 warnings), `bun run typecheck` and `bun run test`. Use `bun run test`, never bare `bun test`.
  - `tools/arena/` changes: `nix build .#checks.x86_64-linux.arena-python` (also part of `nix flake check`) runs the `tools/arena` and `tools/arena/analysis` unit tests in the `dev/` env; inside `nix develop`, `python -m unittest discover -s .` from each directory does the same.
  - Run heavy jobs with `dev heavy --` (niced, at most two at once).
- **Git:** work on `main`. Do branch work in a git worktree. Merge only verified work, with `--no-ff`.
- **Arena work** (tournaments, model endpoints, usage limits): read `docs/arena/README.md` first. Stop only processes you started.
  - Editing the files that play a match (`PLAY_FILES` in `web/src/arena/match.ts`) changes the arena's code hash.
- **Domain terms and decisions:** `CONTEXT.md` and `docs/adr/`.
- **Issues:** this repository's GitHub Issues, through `gh`. Labels and conventions are in `docs/agents/`.
